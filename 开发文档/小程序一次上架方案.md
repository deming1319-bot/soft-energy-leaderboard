# 小程序一次上架方案

> 最近更新：2026-09-30
> 目标：先在管理端验证全部业务规则，再集中完成小程序 UI、微信能力和合规，上架前只产生一个经过完整验收的候选版本。

## 1. 执行原则

管理端测试中心是业务验收入口，后端是唯一业务规则来源，小程序是正式用户的轻客户端。判题、提交时间、作答次数、答案揭晓和榜单排序全部由后端决定，小程序只展示后端结果，不能再实现一套本地规则。

“一次上架”指一次性准备完整后再提审，减少因需求遗漏、隐私不一致和真机问题造成的反复发布。微信审核属于外部流程，无法承诺平台绝不要求补充材料或修改，但项目不得把审核版本当作功能试错版本。

## 2. 上架前固定流程

### A. 管理端业务验收

必须依次通过：

1. 管理员登录；
2. 创建草稿、编辑并发布题目；
3. 测试学员查看题目且无法获取标准答案；
4. 多个测试学员分别提交带表情的精确答案、上下联整体颠倒答案和错误答案，验证冠军、亚军与不入榜；
5. 验证重复点击、作答次数、空答案和截止瞬间提交；
6. 管理员查看原始答案、学员档案和统计；
7. 管理员人工复核并在审计记录中看到变更；
8. 题目截止后揭晓标准答案及冠军/亚军榜；
9. 同等级按首次达到该等级的服务器时间排序；
10. 清理或隔离测试数据，确认其不会进入真实公开榜单。

完成后冻结接口字段、错误码、评分和排序规则。任何业务规则变化都必须先回到管理端重新验收，不直接在小程序版本上试错。

### B. 小程序集中完成

首个正式版本只保留必要页面与功能：

- 首次进入与必要告知；
- 微信身份登录；
- 修习名设置与公开范围说明；
- 题目列表、状态和剩余时间；
- 题目详情、答案填写、确认提交和失败重试；
- 即时判定结果与截止后标准答案；
- 截止后冠军榜、亚军榜和“我的结果”；
- 个人修习档案；
- 隐私保护指引、用户协议、个人信息清单、信息更正和账号注销入口；
- 反馈与举报、评分申诉、处理进度和处理回复；
- 加载、空数据、无网络、服务异常、未开始、已截止和授权拒绝状态；
- 适配中高龄用户的大字号、足够点击区域、明显状态和安全区。

首版不主动收集手机号、微信头像、位置、通讯录等非必要信息。用于榜单展示的修习名需要用户主动填写，并清楚说明截止后会对参与者展示。

### C. 真实微信与真机验收

以下条件必须具备后才能声称“小程序完成”：

- 真实小程序 AppID/AppSecret；
- 已备案 HTTPS API 域名及微信后台 request 合法域名；
- 生产或预发布环境关闭微信模拟登录；
- 至少两个真实微信账号完成身份隔离测试；
- iOS、Android 各至少一台真机验证；
- 验证弱网、断网、切后台、重复点击、Token 失效和截止边界；
- 确认前端包、网络响应和日志均不泄露标准答案或 AppSecret。

## 3. 隐私与数据最小化基线

| 数据 | 首版是否处理 | 用途 | 展示范围 |
| --- | --- | --- | --- |
| 微信 OpenID | 是 | 建立唯一登录身份，防止答题记录串号 | 不对用户或管理员直接展示 |
| 修习名 | 是 | 个人档案与截止后榜单 | 当前用户、管理员、榜单参与者 |
| 答案与成绩 | 是 | 判题、复核、个人记录和排名 | 当前用户与管理员；公开榜单只显示修习名、等级和时间 |
| 提交时间 | 是 | 截止校验和同等级排序 | 当前用户、管理员和截止后榜单 |
| 举报与申诉 | 是 | 受理内容投诉、评分申诉和隐私请求 | 当前用户与管理员 |
| 手机号 | 否 | 当前核心业务无必要用途 | 不收集 |
| 微信头像 | 否 | 文字头像可以满足识别需要 | 不收集 |
| 位置、通讯录、相册 | 否 | 与答题无关 | 不收集 |

隐私保护指引中的数据类型、处理目的和代码实际行为必须一致。正式文本还需要业务主体全称、联系邮箱或电话、注册地址、数据保存期限和注销处理时限；这些信息不能由开发人员猜写。

账号注销采用“删除身份与原始答题内容、停止登录、单场最佳荣誉保留不可关联匿名快照”的口径。匿名快照不包含原用户 ID、原始答案或跨活动标识；生产备份最长 30 日自动轮换。

## 5. 发布门禁

以下任意一项未通过，不提交微信审核：

- 管理端完整业务回归失败；
- 测试数据仍可能出现在正式榜单；
- 生产仍使用 `admin/123456`、默认 JWT 密钥或默认手机号加密密钥；
- 小程序仍使用模拟微信登录、本机 HTTP 地址，或服务器未配置与项目 AppID 对应的 AppSecret；
- 隐私保护指引与实际数据处理不一致；
- 修习名或答案等用户输入未经过内容安全策略；
- 真机存在无法登录、无法提交、重复提交、答案泄露或跨用户串号；
- UI 在常见机型、系统大字体或安全区下出现遮挡；
- 尚未完成备份、回滚和生产健康检查。
- 举报工单无法提交、无法在后台处理或用户无法看到处理回复；
- 账号注销后仍能从业务库读取原始答案或重新关联原用户；
- 首版题库包含未完成资质确认的宗教教义、宗教教育或师门讲解内容。

## 6. 当前结论

业务代码已经达到“提审候选版”范围：答题主链路、举报闭环、注销清除、微信隐私授权同步、原生 WXML 模板和首页备案展示均已完成代码侧验收，正式 AppID 格式检查已通过，服务器 AppSecret 已写入受限生产配置。当前仍不能直接提交审核，外部阻塞项包括 `ruannengliang.top` 备案审核、`api.ruannengliang.top` 正式 HTTPS、微信服务器域名配置、运营主体资料、APP 备案信息、平台隐私指引、服务类目/资质确认与真机体验版验收。资料补齐后才能让发布门禁通过并生成唯一审核候选版本。
