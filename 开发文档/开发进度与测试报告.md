## 3. 联调中发现并修复的问题

真实 MySQL 启动时发现 Flyway 的 UUID 与手机号摘要使用 `CHAR`，而 JPA 模型按 `VARCHAR` 校验，导致启动失败。已统一为 `VARCHAR` 并重新完成 Flyway 建表和 Hibernate 校验。该问题只有真实数据库启动才能发现，现已修复。

管理端首次浏览器检查发现缺少 favicon 导致一个 404 控制台错误；已加入自定义印章图标，再次检查为 0 错误。

2026-08-07 上线终检发现 `miniapp/project.config.json` 存在孤立文本导致 JSON 无法解析，现已修复并把 JSON 解析失败纳入发布门禁。同时发现业务 WXML 使用了多种 HTML 风格标签，已全部替换为微信原生 `view/text` 并同步样式选择器；发布门禁现在会阻止同类问题再次进入候选版本。

2026-10-13 小程序 `1.0.1` 体验版首次请求正式 API 时，生产后端把微信 `text/plain` Content-Type 的 JSON 响应直接反序列化为 `Map`，触发 `UnknownContentTypeException`。提交 `edd5bc8` 改为先读取字符串再用 Jackson 解析，覆盖微信登录和内容安全相关接口；Jenkins 第 10 次构建部署后，真实微信登录恢复。

真实微信登录恢复后，首次保存修习名仍显示内容安全暂不可用。服务器使用同一凭据、最新用户 OpenID 和相同文本直接调用微信接口，`scene=1`、`scene=2` 均返回 `errcode=0`、`suggest=pass`，将问题收敛到 Java 请求格式。`f2bead1`、`8be40e5`、`8d92892` 依次补齐 Token 刷新、构造器注入和错误响应兼容；最终提交 `d337d68` 使用显式 UTF-8 JSON 字节体、内容类型、内容长度和昵称场景。Jenkins 第 16 次构建已部署到 `/opt/soft-energy/releases/16`，真机保存修习名并进入首页成功，问题闭环。

2026-10-14，微信审核以首页无法加载完整数据、页面报错为由驳回 `1.0.2`。线上 API 同期仍为 HTTPS 200/`UP`，排除生产服务整体宕机。代码复核发现审核包可能以 `envVersion=develop` 运行，而原逻辑会据此请求 `127.0.0.1:8081` 并启用开发测试能力。现新增“`envVersion=develop` 且 `platform=devtools`”双重条件：只有微信开发者工具模拟器使用本机 API，真实审核设备上的开发版以及体验/正式版全部使用正式 HTTPS API；同时模拟设备标识、测试会话和测试中心也受同一条件保护。

修复提交 `bcbf727` 推送后，真实手机扫描开发者工具预览码已成功进入首页并加载生产题目数据，直接验证了待审开发包在真实设备上不再访问 localhost。该验证覆盖审核驳回的首页可用性问题；完整作答、结果和个人记录仍需纳入重新提审录屏。

2026-10-15，`1.0.3` 审核进一步指出两项合规问题：用户进入首页前被要求登录，以及未选择“教育服务—教育信息展示”服务类目。代码现已将首页设为首屏，允许游客读取已发布题目列表和题目正文；只有参与答题、查看个人记录、榜单或举报等操作才进入登录流程，且不收集手机号、微信头像或微信昵称。服务类目属于微信平台配置，必须由项目负责人补选后再提交 `1.0.4`。
