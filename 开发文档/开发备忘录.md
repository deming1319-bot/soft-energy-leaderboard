## 3. 首次推送前固定清单

当用户明确提出“现在推送到 GitHub”后，按以下顺序执行：

1. 项目交接人注册 GitHub 账号，完成邮箱验证并开启双重验证；
2. 确认 GitHub 组织名称和组织管理员；
3. 开通 GitHub Team，并把交接人加入组织；
4. 创建组织私有仓库 `soft-energy-leaderboard`；
5. 配置 `main` 和 `v*` Rulesets；
6. 创建 Issue 标签、首个 Milestone 和 PR 模板；
7. 创建最小权限 `soft-energy-jenkins` GitHub App；
8. 对本地文件执行密钥、个人信息、大文件和忽略规则检查；
9. 确认首次提交内容和提交说明；
10. 配置 Remote 并执行首次推送；
11. 在 GitHub 上复核仓库可见性、分支规则、文件完整性和敏感信息检查结果；
12. 记录仓库地址、首次提交号和交接成员，不在文档中记录任何凭证。

## 4. 交接原则

- 正式仓库归属 GitHub 组织，不归属某位开发人员的个人账号；
- 交接人只获得工作所需权限，不直接共享其他人的账号或 Token；
- 人员变化时通过组织成员权限交接，不复制个人凭证；
- Jenkins 使用 GitHub App，不绑定交接人的个人登录状态；
- 交接前必须确保至少有一名可用的组织管理员，避免仓库无人管理；
- 任何账号、套餐或权限变化都要更新本备忘录的“状态”，但不得写入真实密钥。
