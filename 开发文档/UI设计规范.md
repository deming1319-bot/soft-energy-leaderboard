# Soft Energy Leaderboard UI 设计规范

> 文档状态：企业级视觉方向、组件策略与设计先行门禁已锁定（V0.4）  
> 创建日期：2026-07-26  
> 最近更新：2026-07-26  
> 适用范围：微信小程序与 Web 管理后台

## 1. 设计判断

本产品的 UI 不是“古风装饰皮肤”，而是儒、释、道文化内容和师父原创思想在数字产品中的现代呈现。

核心设计命题是：

> 如何让具有文化厚度的内容，在手机上保持庄重、清晰、易操作，同时不让 30—60 岁用户感到陈旧、复杂或有距离感。

设计关键词：

- 温润；
- 清明；
- 克制；
- 有秩序；
- 当代东方；
- 易读；
- 平静但不沉闷。

不使用的方向：

- 黑底大金字的“会所式国风”；
- 大面积宫墙红、亮金渐变和发光描边；
- 宣纸、竹简、卷轴效果铺满所有页面；
- 莲花、八卦、祥云、竹子、佛像、香炉等符号同时堆叠；
- 模仿寺庙、道观或古籍页面，牺牲移动端可读性；
- 为了“禅意”使用低对比度浅灰小字；
- 长时间水墨开场、飘动粒子和影响答题的背景动画；
- 与实际思想内容无关的 AI 式东方幻想插画。

## 2. 目标用户与设计影响

### 2.1 用户范围

- 主要用户：30—60 岁；
- 当前重点：约 35—60 岁；
- 预期中高龄用户占比较高；
- 师父约 80 岁，是核心内容指导者，但首版不要求直接操作后台。

### 2.2 设计策略

| 用户特征 | 设计应对 |
| --- | --- |
| 阅读国学或哲学内容 | 提高正文宽松度、行距和段落层次，避免信息拥挤 |
| 对小字和低对比度更敏感 | 默认使用较大字号和深色正文，提供大字模式 |
| 不一定熟悉年轻化手势 | 主要功能必须有可见按钮，不依赖隐藏侧滑或长按 |
| 容易误触 | 加大点击区域，高影响操作二次确认 |
| 关注内容权威与庄重 | 明确内容分类、出处和师父讲解，不使用娱乐化文案 |
| 希望操作简单 | 一级页面不超过 3—4 个，减少层层跳转 |

## 3. 视觉主题：当代东方书院

### 3.1 视觉叙事

界面像一间光线柔和、安静、有人使用的现代书房，而不是仿古景区页面。

视觉层次建议：

1. 大面积温暖米白背景，降低纯白屏幕的刺激；
2. 墨色正文和清楚标题，建立阅读秩序；
3. 每页只使用一种文化视觉焦点，例如一段淡墨山水、一枚印章或一道器物纹样；
4. 朱砂红、松柏青用于功能和状态，铜金只做少量等级点缀；
5. 卡片边界尽量通过留白和轻微色差表达，不依赖厚阴影。

### 3.2 推荐配色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--color-bg` | `#F5F1E8` | 小程序主背景，温暖纸色 |
| `--color-surface` | `#FFFDF8` | 卡片、输入区、弹窗 |
| `--color-ink` | `#26241F` | 主标题、正文 |
| `--color-ink-secondary` | `#666158` | 次要说明，仍需保证对比度 |
| `--color-line` | `#DDD5C8` | 分隔线和输入边界 |
| `--color-cinnabar` | `#8F3D30` | 主按钮、冠军重点、印章点缀 |
| `--color-cinnabar-dark` | `#743027` | 主按钮按下状态 |
| `--color-pine` | `#365247` | 完成状态、亚军辅助色、个人中心 |
| `--color-bronze` | `#947647` | 极少量等级、时间或纹样点缀 |
| `--color-warning` | `#A45F27` | 截止提醒、需复核 |
| `--color-error` | `#A13732` | 错误、提交失败 |

使用规则：

- 一个页面主强调色最多一种；
- 铜金色不能用于大段文字；
- 朱砂红不与高饱和金色大面积并用；
- 任何状态都不能只靠颜色表达，必须同时有文字或图标；
- 正文与背景对比度目标不低于 4.5:1。

### 3.3 字体

小程序不建议首版加载体积较大的完整中文网络字体包。

推荐字体栈：

```css
/* 正文、按钮、表单 */
font-family: "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;

/* 页面大标题、短句、引文标题 */
font-family: "Songti SC", "STSong", "Noto Serif CJK SC", serif;
```

使用规则：

- 宋体只用于标题、栏目名和不超过两三行的短句；
- 题目正文、答案输入、按钮和数据列表统一使用无衬线字体；
- 不使用难以辨认的书法字体作为功能文字；
- 如果未来定制题字，只用于品牌标识，不替代正文。

### 3.4 字号与行高

以下以接近 CSS px 的视觉尺寸表达，开发时换算为小程序 `rpx` 并进行真机校准：

| 场景 | 标准模式 | 大字模式 | 行高建议 |
| --- | --- | --- | --- |
| 品牌/页面大标题 | 26—30 | 30—34 | 1.25—1.35 |
| 题目标题 | 22—24 | 25—28 | 1.4—1.5 |
| 题目正文 | 20—22 | 23—26 | 1.65—1.75 |
| 普通正文 | 18 | 21—22 | 1.6—1.7 |
| 按钮文字 | 18 | 20 | 1.2 |
| 次要说明 | 15—16 | 18 | 1.5 |
| 时间和数字 | 16—20 | 19—23 | 1.3 |

不得使用 12px 或更小文字承载关键说明、截止时间、判定原因和隐私提示。

### 3.5 圆角、阴影与边界

- 主卡片圆角：12—16px；
- 按钮圆角：10—14px，不使用过度胶囊化；
- 标签圆角：6—8px；
- 卡片阴影：非常轻，优先使用边界色差；
- 输入框保持明显边界和聚焦状态；
- 不使用多层玻璃拟态和透明渐变。

### 3.6 图像与纹样

推荐素材方向：

- 经授权的师父题字、印章、照片或手稿局部；
- 有明确授权的山水、器物、古籍版画和纸张肌理；
- 为项目原创或定制的抽象山形、水纹、回纹和印章图形；
- 极淡、低信息密度的水墨背景，仅用于页头或空状态。

素材规则：

- 每页最多一个主要图像焦点；
- 不把佛像、神像、法器等宗教对象当普通装饰图标；
- 儒、释、道元素分别使用时应符合对应内容，避免符号错配；
- 背景纹理透明度应很低，不能干扰正文；
- 图片必须压缩，并提供纯色背景降级方案。

第三方设计网站和“数字故宫”等产品只用于研究构图、色彩和信息层级，不直接复制界面。花瓣等平台中的作品不等于可商用素材，未取得许可不得拿原图上线。

## 4. 小程序信息架构

首版底部导航建议控制为三个：

1. `修习`：当前题目、即将开始、已结束活动；
2. `榜单`：当前或最近一场冠军榜、亚军榜；
3. `我的`：个人资料、参与记录和设置。

不建议使用只有文化意味但不明确的一级名称，例如单独使用“问道”“观心”“悟境”。可以把这些词作为栏目副标题，但主导航必须让用户一眼看懂。

## 5. 小程序核心页面设计

### 5.1 启动与登录

目标：让用户快速进入，不用先看复杂文化介绍。

页面内容：

- 简洁品牌名称；
- 一句不超过两行的定位语；
- 一处淡墨或师父题字视觉；
- “微信登录”主按钮；
- 隐私政策和个人信息用途说明。

登录成功不等于已经获得手机号、头像或昵称。手机号授权在业务需要出现时单独说明，不使用连续弹窗强迫授权。

### 5.2 修习首页

页面结构：

1. 顶部：问候、用户展示名称、大字模式入口；
2. 当前活动卡：活动主题、所属分类、开始/截止时间；
3. 清晰状态：未开始、进行中、已提交、已截止；
4. 主要按钮：“开始答题”“继续作答”或“查看结果”；
5. 最近修习记录；
6. 一条短小的内容引导或师父寄语。

当前活动是首页唯一主视觉，不能同时放大量轮播图、功能宫格和资讯列表。

### 5.3 题目详情与答题

页面结构：

```text
栏目分类 / 活动名称
距离截止还有 7 小时 32 分
────────────────────
题目正文（大字、宽行距、清晰分段）
必要的出处或背景说明
────────────────────
我的回答
[大面积多行输入区]
已输入 126 字
[保存草稿]  [确认提交]
```

交互要求：

- 进入页面后先看到完整题目，不被装饰图遮挡；
- 长题目支持正常滚动，不能横向滑动阅读；
- 输入区最小高度足够写完整答案；
- 输入过程自动保存本地草稿，并明确显示保存状态；
- 提交前展示二次确认，说明能否继续修改；
- 提交请求期间按钮锁定，避免重复点击；
- 提交成功显示服务器接收时间。

### 5.4 判定结果

结果页需要平静、明确，不做游戏式爆炸特效。

- 冠军：朱砂印章式等级标识，文案强调“答案完整且顺序符合要求”；
- 亚军：松柏青或铜色等级标识，明确是要点缺失、顺序问题还是需要复核；
- 未入榜：中性表达，例如“本次答案暂未达到入榜标准”，避免“失败”“太差”等打击性语言；
- 活动进行中默认不展示完整标准答案；
- 如允许继续作答，按钮明确显示“完善答案”；
- 如不允许重答，显示“已完成提交”和最终提交时间。

### 5.5 排行榜

页面结构：

- 活动名称与截止时间；
- `冠军榜` / `亚军榜` 两个清晰标签页；
- 当前用户结果固定在可见区域，但不遮挡列表；
- 每行展示名次、头像或占位图、展示名称、有效提交时间；
- 前三名可加强层级，但不使用巨大领奖台挤压其他名单；
- 昵称较长时合理截断，个人详情中可看完整名称；
- 空榜明确显示“本场暂时还没有冠军/亚军”。

排行榜强调“答得完整且及时”，不设计连续闪烁、攀比口号或刺激性倒计时。

### 5.6 我的

页面结构：

- 头像和展示名称；
- 本人手机号；
- 参与次数、冠军次数、亚军次数；
- 最近答题记录；
- 字体大小设置；
- 隐私政策、用户资料管理和退出登录。

设置项使用完整文字，不使用只有齿轮图标的隐藏入口。

## 6. 管理后台视觉与页面

### 6.1 技术与风格

管理后台使用 Vue 3 + TypeScript + Vite + Element Plus。

后台以高效、清晰为第一目标，不把小程序的国风背景直接搬进数据表格。文化感仅通过以下方式体现：

- 米白或浅暖灰整体背景；
- 墨色标题；
- 朱砂色主按钮和选中状态；
- 少量细线或页头纹样；
- 与小程序一致的品牌标识。

表格、筛选、弹窗、分页仍遵循常规管理系统习惯。

### 6.2 页面导航

首版菜单建议：

1. 数据概览；
2. 答题活动；
3. 答题记录；
4. 排行榜；
5. 小程序用户；
6. 操作日志；
7. 修改密码。

只保留真实功能，不放“系统管理、权限管理、部门管理、岗位管理”等当前没有业务的模板菜单。

### 6.3 创建活动页面

采用分区表单，不把全部配置塞入一个长弹窗：

1. 基本信息：名称、分类、简介；
2. 题目内容：题干、背景、出处；
3. 标准答案：标准文字、关键要点、顺序要求；
4. 判定规则：冠军、亚军、待复核门槛；
5. 活动时间：开始、截止、榜单公开；
6. 提交规则：是否允许重答、是否显示结果；
7. 发布预览：以学生视角检查题目页。

标准答案区必须带有“仅管理员和判题服务可见”的明确提示。

### 6.4 数据统计

首页只展示对运营有用的数据：

- 小程序用户总数；
- 当前活动参与人数；
- 已提交人数；
- 冠军、亚军、未入榜、待复核人数；
- 最近提交；
- 需要人工处理的异常。

图表不超过 2—3 个，能用数字卡和表格说清楚的内容不强行画图。

## 7. 交互与动效规范

### 7.1 动效时长

| 场景 | 建议时长 |
| --- | --- |
| 按钮按下和颜色变化 | 100—160ms |
| 卡片、弹窗进入 | 180—240ms |
| 页面局部内容切换 | 200—260ms |
| 成功状态出现 | 220—320ms |

动效优先使用透明度和轻微位移，避免大幅缩放、旋转和弹跳。

### 7.2 加载反馈

- 页面首屏使用与内容形状接近的骨架屏；
- 提交答案使用明确按钮加载状态；
- 超过 2 秒的请求显示文字说明；
- 失败时保留用户输入并提供“重新提交”，不能清空答案；
- 网络恢复后不得偷偷重复提交。

### 7.3 操作反馈

- 点击后立即出现视觉反馈；
- 保存草稿显示“已保存”及最近保存时间；
- 截止前 30 分钟可使用温和提醒，但不连续弹窗；
- 表单错误定位到具体字段；
- 提交成功后显示服务器时间和当前判定状态。

## 8. 最终组件方案

### 8.1 小程序

小程序基础组件固定采用 TDesign Miniprogram：

- Button；
- Input / Textarea；
- Dialog；
- Tabs；
- Toast；
- Loading / Skeleton；
- Cell；
- Empty；
- Popup；
- Countdown（是否直接使用需评估可读性）。

所有组件需要覆盖项目色彩、字号、圆角和间距，不能保持默认蓝色主题。组件库源码和 `node_modules` 不直接修改，通过项目主题变量、样式包装层和业务组件封装完成定制。

需要自研的业务组件：

- 文化活动卡；
- 题目阅读卡；
- 答题状态条；
- 冠军/亚军等级标识；
- 排行榜行；
- 本人排名固定条；
- 大字模式切换；
- 内容出处与师父讲解模块。

建议业务组件命名：

```text
culture-page-header     # 东方书院页头
practice-activity-card  # 修习活动卡
question-reader         # 题目阅读区
answer-editor           # 答案编辑与草稿状态
result-seal             # 冠军/亚军结果标识
ranking-list            # 排行榜列表
my-rank-bar             # 本人排名固定条
font-size-switch        # 标准/大字模式
content-source-note     # 出处、师父讲解和编辑说明
```

### 8.2 管理后台

管理后台基础组件固定采用 Element Plus：

- Form；
- Table；
- Pagination；
- DateTimePicker；
- Dialog / Drawer；
- Tabs；
- Descriptions；
- Tag；
- Alert；
- Skeleton；
- Upload（后续确有图片和附件时再启用）。

不引入第二套同类后台组件库，避免样式、交互和包体混乱。

管理后台自研业务组件：

```text
StatCard                # 统计数字卡
ActivityStatus          # 活动状态与截止信息
JudgmentBadge           # 冠军/亚军/未入榜/待复核
LeaderboardPreview      # 榜单预览
QuestionContentEditor   # 题目、出处和讲解编辑区
AnswerRuleEditor        # 标准答案、要点和顺序规则
MaskedPhoneCell         # 手机号脱敏与受控查看
SubmissionTimeline      # 学生多次提交时间线
```

### 8.3 主题实现方式

小程序：

- 在 `app.wxss` 和独立主题文件中维护颜色、字号、间距和圆角变量；
- TDesign 组件外层使用项目业务组件统一封装，不在各页面重复覆盖样式；
- 页面布局使用原生 WXSS；
- 丝滑动效使用 WXSS `transition`、`transform` 和微信原生动画能力；
- 不引入第三方重型动画库。

管理后台：

- 使用 CSS Variables + SCSS 维护主题；
- 通过 Element Plus 主题变量统一修改主色、圆角、表格和表单样式；
- 使用 Vue `Transition` 和 CSS 完成 180—260ms 状态过渡；
- ECharts 仅负责必要统计图，颜色统一读取项目主题；
- 不修改 Element Plus 包内源码。

### 8.4 组件使用边界

直接使用组件库的部分：按钮、输入框、弹窗、提示、分页、表格、日期选择、加载、空状态等通用交互。

必须自研展示的部分：首页活动卡、题目阅读、结果印章、排行榜、本人排名、师父讲解、内容出处和国学页头。

最终页面不是“TDesign 默认页面”或“Element Plus 默认后台”，而是使用成熟组件保证交互稳定，再由自研业务组件建立产品识别。

明确不使用：

- 不使用 Vant Weapp；
- 不使用第二套小程序组件库；
- 不使用 Ant Design Vue；
- 不使用整套后台模板；
- 不使用 GSAP 等重型动效库；
- 不为了国风效果全部自研表单、弹窗和基础控件。

## 9. 内容设计规范

### 9.1 名称与措辞

产品可以有文化气质，但操作文案必须直白：

| 不推荐 | 推荐 |
| --- | --- |
| 入境 | 开始答题 |
| 证悟 | 查看结果 |
| 登坛 | 查看榜单 |
| 法门已启 | 活动已开始 |
| 缘尽 | 活动已截止 |

文化词可作为标题或副标题，核心按钮仍使用用户熟悉的表达。

### 9.2 内容来源展示

建议为每道题预留：

- 文化分类：儒、释、道、融通、师父原创；
- 经典或材料名称；
- 原文出处；
- 师父讲解；
- 编辑整理说明；
- 内容版本；
- 审核状态。

不得把师父原创解释写成经典原文，也不得把现代译文、网络文章或他人注释当作无版权限制的公共文本。

## 10. 美术素材与版权底线

素材来源优先级：

1. 师父或项目方拥有版权并明确授权的题字、手稿、印章、照片；
2. 为本项目原创绘制或定制的图形和插画；
3. 明确属于公共领域或提供可商用许可的博物馆、开放图库素材；
4. 经正式购买并符合小程序商业使用范围的素材。

不能因为素材能在花瓣、搜索引擎或“画框”平台看到，就默认可以下载上线。任何第三方原画进入项目前，应记录作者、来源、许可范围和证明文件。

如果以后使用 AI 生成东方视觉素材，必须统一提示词、构图、色彩和文化符号规则，并由熟悉儒、释、道内容的人审核，避免错误文字、错误器物和宗教符号混用。

## 11. 设计验收标准

### 11.0 设计先行门禁

后端、数据库和基础工程可以先开发，但小程序与管理后台的正式业务页面不得跳过以下流程直接套组件库：

1. 视觉研究：在开始核心页面编码前，先研究当代东方文化产品、成熟内容型小程序、企业级管理后台和适老化产品，形成不少于 12 个有效参考的视觉研究板；每个参考必须记录“值得借鉴的方法”和“不适合本项目的部分”，不能只保存截图。
2. 视觉母版：先确定色彩、字体、字号、间距、圆角、描边、阴影、图标、纹理和动效 Token，产出小程序与管理后台各一套视觉母版。
3. 核心线框：先完成小程序首页、活动答题、结果、排行榜和“我的”，以及管理后台登录、数据概览、活动编辑、答题记录和榜单页面的线框关系。
4. 高保真基线：小程序至少先完成“首页 + 答题 + 结果/榜单”，管理后台至少先完成“数据概览 + 活动编辑 + 答题记录”高保真基线，再批量开发其他同类页面。
5. 多尺寸检查：小程序基线检查常见窄屏、主流屏和大字模式；后台基线检查 1366px、1440px、1920px。
6. 评审后编码：高保真基线通过层级、可读性、品牌一致性和目标用户可操作性检查后，才能固化为组件和页面代码。

视觉研究只借鉴信息层级、留白、节奏和交互方法，不复制第三方页面、插画、书法、纹样或品牌资产。研究素材不得未经授权直接进入正式产品。

以下任一情况出现，UI 直接判定不合格并返工：

- TDesign 默认蓝色、Element Plus 默认蓝色或默认组件尺寸仍能一眼识别；
- 只更换主色，布局、卡片、表格、侧栏和登录页仍是组件库演示结构；
- 管理后台直接套用通用模板的 Logo 区、菜单、面包屑、标签栏和大屏图表；
- 页面由大量同尺寸白卡片机械堆叠，没有清晰的主次关系和阅读节奏；
- 为了显得“国学”而堆砌宣纸、卷轴、祥云、亮金渐变、书法字和宗教符号；
- 为了显得“现代”而堆砌玻璃拟态、霓虹光效、科技线条、无意义渐变或大面积悬浮阴影；
- 小程序和管理后台各页面自行定义颜色、间距和圆角，无法追溯到统一 Token；
- 图标来源、线宽和视觉重量混乱，或直接混用多套图标风格；
- 页面看似精致，但 30—60 岁用户无法快速找到题目、提交、发布、复核和查看榜单等核心动作；
- 仅凭开发人员主观评价“好看”，没有截图对照、尺寸检查和目标用户任务验证。

组件库的定位是“交互和可访问性的底座”，不是视觉成品。按钮、表单、弹窗、表格等可以复用成熟行为，但页面骨架、信息层级、品牌头部、活动卡、题目阅读、结果印章、榜单行、统计卡和关键状态必须按本项目重新设计。

### 11.1 小程序

1. 30—60 岁测试用户无需解释即可找到题目、提交答案、查看结果和榜单。
2. 题目正文在常见手机上无需放大即可阅读。
3. 标准模式和大字模式都不出现文字截断、按钮遮挡和布局溢出。
4. 普通点击区域不小于约 44×44px，主要按钮高度达到 48—56px。
5. 关键正文对比度达到 4.5:1 目标。
6. 页面在弱网下不会丢失已经输入的答案。
7. 提交按钮连续点击不会生成重复记录。
8. 文化装饰不覆盖内容、不降低读取速度。
9. 不出现未经授权的原画、字体、书法和照片。
10. 儒、释、道相关图形和文案经过内容审核。

### 11.2 管理后台

1. 管理员可以在不阅读技术说明的情况下创建并发布一场活动。
2. 标准答案与学生可见题目在界面上明确分区。
3. 用户、提交、判定和榜单之间可以相互追溯。
4. 统计数字与列表筛选结果一致。
5. 管理列表默认脱敏手机号。
6. 主要页面在 1366px 及更宽桌面显示正常，并具备基本的窄屏浏览能力。
7. 页面没有模板残留菜单、无效按钮和无业务价值的图表。

### 11.3 企业级与现代化验收

1. 组件库默认主色、字号、圆角和间距不得直接作为最终视觉交付。
2. 所有页面使用同一套颜色、字体、间距、圆角、阴影和动效 Token。
3. 首屏使用骨架屏，局部操作不触发无必要的整页刷新。
4. 常规状态切换控制在 180—260ms，低性能设备上不得出现明显卡顿。
5. 网络请求期间提供准确反馈，失败后保留用户输入并允许安全重试。
6. 管理后台在 1366px、1440px、1920px 桌面宽度下保持合理信息密度。
7. 小程序完成主流 iOS、Android 微信版本及不同字号设置的真机检查。
8. TypeScript 开启严格模式，UI 代码通过 ESLint、Prettier 和 Stylelint。
9. 核心管理页面通过 Vitest 组件测试和 Playwright 流程测试。
10. UI 交付必须通过目标用户可用性测试，不能只由开发人员主观判断“好看”。

## 12. 设计参考与研究结论

参考“数字故宫”等文化数字产品的不是具体皮肤，而是方法：

- 传统文化内容可以通过简化的现代布局呈现；
- 底部导航、明确入口和实用功能优先于装饰；
- 克制的米色、宫红、金色和器物纹样可以建立文化识别；
- 面向中高龄用户，需要同步重视无障碍、字号和点击区域。

工信部适老化通用设计规范建议移动应用主要文字可调整，适老界面主要文字不小于 18dp/pt，普通页面主要组件点击区域不小于 44×44dp/pt。W3C WCAG 2.2 对普通文字提出至少 4.5:1 的对比度目标。本项目不单独制作“老人版”，而是在默认界面中直接采用更易读的基线，并增加大字模式。
