## 1. 最终结论

当前首次上线只执行以下方案，不使用生产 Docker Compose、Kubernetes 或手工覆盖文件：

```text
GitHub 公开仓库
  -> Jenkins LTS Pipeline（阿里云 ECS 本机，单执行器）
  -> 后端/管理后台/小程序质量门禁
  -> 不可变版本目录
  -> 原子切换 current 软链接
  -> systemd 重启 Java 21 服务
  -> Nginx 托管管理后台并反代 /api/v1
  -> ECS 本机 MySQL 8.0.46（仅监听 127.0.0.1）
  -> 本机和公网健康检查
  -> 失败自动恢复上一应用版本
```

当前 Jenkins 负责小程序类型检查、测试和 npm 构建；项目 AppID 已配置，微信上传私钥和机器人编号补齐后才启用微信 CI 上传。体验版验证、提交审核和正式发布必须人工完成。数据库只允许 Flyway 向前迁移；应用可以自动回退，数据库不做自动向下迁移。

## 4. 网络和安全边界

### 4.1 端口

| 端口 | 监听地址 | 用途 | 是否公网开放 |
| --- | --- | --- | --- |
| 22 | ECS 公网地址 | SSH 运维 | 仅管理员固定 IP |
| 80 | ECS 公网地址 | HTTPS 跳转 | 是 |
| 443 | ECS 公网地址 | 管理后台和 API | 是 |
| 8080 | `127.0.0.1` | Jenkins | 否 |
| 8081 | `127.0.0.1` | Spring Boot API | 否 |
| 18080 | `127.0.0.1` | Jenkins 发布后检查 Nginx 管理端 | 否 |
| 18081 | `127.0.0.1` | Jenkins 候选包临时冒烟 | 否 |
| 3306 | `127.0.0.1` | MySQL | 否 |

安全组不得公开 8080、8081、18080、18081、3306。当前 Jenkins 由 Nginx 暂时代理为：

```bash
http://123.56.169.70/jenkins/
```

该入口只用于初始化阶段，正式域名和证书就绪后切换 HTTPS 并限制访问来源。Jenkins 本体仍只监听 `127.0.0.1:8080`。

### 4.2 账号隔离

- `root`：只用于首次服务器配置，不运行应用；
- `jenkins`：只构建、写入发布目录，并通过最小 sudo 规则重启指定服务；
- `softenergy`：只运行 Java 服务，不能登录系统；
- `nginx`：只读取管理后台静态文件；
- `softenergy_runtime`：生产业务读写账号；
- `softenergy_migrator`：只供 Flyway 迁移使用；
- `softenergy_ci`：只能访问 `soft_energy_ci`。

Jenkins 的 sudo 白名单只允许：

```text
systemctl restart soft-energy-api
systemctl status soft-energy-api
journalctl -u soft-energy-api -n 200 --no-pager
```

Nginx 配置不是每次发布内容，正常应用发布不需要 Jenkins 重载 Nginx。

## 6. systemd 和 Nginx 职责

### 6.1 systemd

服务名固定为：

```text
soft-energy-api.service
```

核心约束：

- `User=softenergy`、`Group=softenergy`；
- `ExecStart` 指向 `/opt/soft-energy/current/api/soft-energy-api.jar`；
- 生产配置从 `/etc/soft-energy/application-prod.yml` 和环境文件加载；
- `Restart=on-failure`，不使用无限快速重启；
- 开启 `NoNewPrivileges`、`PrivateTmp`、`ProtectSystem` 等 systemd 加固；
- 优雅停止超时 30 秒；
- Java 堆上限按 ECS 内存设置，首版固定不超过 2 GiB。

### 6.2 Nginx

Nginx 固定承担：

- 将 `/opt/soft-energy/current/web` 作为 Vue 静态根目录；
- `try_files $uri $uri/ /index.html` 支持 Vue Router；
- `/api/v1/` 反向代理到 `http://127.0.0.1:8081`；
- 设置 `X-Real-IP`、`X-Forwarded-For`、`X-Forwarded-Proto`；
- 统一 HTTPS、压缩、缓存、安全响应头和访问日志；
- `/swagger-ui`、`/v3/api-docs`、Actuator 详细端点在生产公网返回 404；
- 对登录、手机号授权和答题提交接口配置合理限流，不能影响正常集中答题。

### 7.2 分支和 Pull Request

- 日常功能分支：`feature/<issue编号>-<简短英文>`；
- 缺陷分支：`fix/<issue编号>-<简短英文>`；
- 文档分支：`docs/<issue编号>-<简短英文>`；

- 禁止直接推送 `main`，所有变更必须通过 Pull Request；

- PR 必须通过 `jenkins/ci` 严格状态检查，并与最新 `main` 保持同步；
- 只允许 Squash merge，合并后自动删除源分支，保持线性历史；
- 首版单人维护时不强制第二人批准，但 PR、CI 和变更说明仍为强制门禁；有第二位维护者后，Ruleset 固定增加 1 个批准要求；
- 禁止从开发人员电脑直接复制 jar 或 `dist` 到生产服务器；
- 禁止在 Jenkins 工作区中手工修改代码后发布。

### 7.3 Rulesets

`main` 分支规则集固定开启：

- Require a pull request before merging；
- Require status checks to pass：`jenkins/ci`；
- Require branches to be up to date before merging；
- Require linear history；
- Block force pushes；
- Restrict deletions；
- 仓库管理员只在生产故障处置时临时旁路，并在 Issue 和审计记录中写明原因。

`v*` 标签规则集固定开启：

- 只有仓库管理员/发布负责人可以创建；
- 禁止更新已经存在的正式标签；
- 禁止删除正式标签；
- 标签必须指向 `main` 上已通过 `jenkins/ci` 的提交。

### 7.4 Issue、里程碑和标签

GitHub Issue 是开发任务和缺陷的唯一编号来源。固定标签如下：

```text
type:feature  type:bug  type:docs  type:security
priority:P0  priority:P1  priority:P2  priority:P3
area:miniapp  area:admin  area:backend  area:database  area:deploy
```

- 每个正式版本建立一个 Milestone，例如 `v0.1.0`；
- P0 为生产中断或数据安全事故，P1 为核心流程不可用；
- PR 模板必须包含需求/Issue、修改范围、测试结果、数据库变更和回退影响；
- Issue、PR 和 Release 中不得填写真实密钥、手机号明文或标准答案全文。

- Release 记录 Git commit、Jenkins 构建号、Flyway 版本和发布时间，不上传生产配置或密钥。

## 8. Jenkins Pipeline

根目录固定维护一个 `Jenkinsfile`，阶段顺序不可任意跳过。

### 8.1 CI 阶段

1. Checkout：使用 `checkout scm` 拉取 Jenkinsfile 对应提交并记录 commit、分支、标签和构建号；
2. Backend Verify：使用 JDK 21 和 Maven 执行单元测试、JaCoCo 和打包；
3. Admin Verify：`pnpm install --frozen-lockfile`，执行 ESLint、Stylelint、TypeScript、Vitest 和 Vite build；
4. Miniapp Verify：锁定依赖，执行 ESLint、TypeScript、单元测试和正式配置构建检查；
5. Migration Verify：校验 Flyway 命名、顺序、校验和，并在 `soft_energy_ci` 从空库完成迁移和核心集成测试；
6. Candidate Smoke：使用 CI 配置把候选 jar 临时启动在 `127.0.0.1:18081`，验证 readiness 后立即停止；
7. Package：生成不可变发布目录和 `release-manifest.json`；
8. Archive：保存 jar、管理后台压缩包、测试报告、覆盖率和 SHA-256。

任一阶段失败立即结束，不允许通过“跳过测试”参数进入生产部署。

### 8.2 生产门禁

只有同时满足以下条件才显示生产发布确认：

- 当前提交带 `vX.Y.Z` 标签；
- 标签提交已通过全部 CI；
- 工作区无未提交修改；
- 依赖锁文件存在且未被忽略；
- 生产配置存在但不打印内容；
- 若包含新 Flyway 文件，已创建并验证可恢复的数据库备份；
- 管理员在 Jenkins `input` 步骤确认版本号、提交号、数据库迁移范围和回退版本。

### 8.3 部署阶段

1. 将发布包复制到 `/opt/soft-energy/releases/<BUILD_NUMBER>`；
2. 校验 jar、`admin/index.html`、manifest 和 SHA-256；
3. 记录当前 `current` 指向作为回退版本；
4. 原子切换 `current`；
5. 重启 `soft-energy-api`；
6. 检查本机 readiness；
7. 检查 Nginx 本机代理、管理后台 HTML 和公网 HTTPS；
8. 成功后标记该版本，清理超过 5 个的旧成功版本；
9. 上传微信小程序开发版本；
10. 写入 Jenkins 发布记录。

健康检查固定包含：

```text
http://127.0.0.1:8081/actuator/health/readiness
https://<正式域名>/api/v1/health
https://<正式域名>/
```

本机检查最多等待 120 秒。超时或任一检查失败时，流水线自动把 `current` 恢复到上一版本、重启服务、再次检查并将构建标记为失败。

## 9. 数据库迁移规则

- 所有表结构变化只通过 `backend/src/main/resources/db/migration/V*.sql`；
- 已在任一共享环境成功执行的迁移文件禁止改名、改内容或删除；
- 禁止 Hibernate `ddl-auto=update/create/create-drop`；
- 禁止生产执行 `flyway clean`；
- 迁移只允许“先扩展、后收缩”：先加兼容字段/表，再发布应用，确认旧版本不再依赖后，另一个维护版本才允许删除旧结构；
- 普通发布不得包含清库、批量覆盖正式数据或不可逆大表更新；
- Flyway 失败时先停止重复重启，保留日志和现场，确认数据库备份点后再处理；
- 不得直接删除 `flyway_schema_history` 中 `success=1` 的记录；
- `flyway repair` 只能在确认失败迁移未留下脏结构或数据后由负责人执行。

应用自动回退不等于数据库回退。因为发布迁移必须保持向后兼容，上一应用版本应能在新结构上继续运行；如果迁移造成数据损坏，则按第 11 节从备份恢复，不执行自动降级 SQL。

- 上传私钥使用 Jenkins Secret File，临时复制后立即清理；
- 私钥文件绝不进入工作区归档、Git 或开发文档；
- 微信公众平台代码上传 IP 白名单只加入 ECS 固定公网出口 IP；
- 上传版本号与 Git 标签一致，描述包含 commit 和 Jenkins 构建号；
- Jenkins 只上传“开发版本”，不自动提交审核或自动发布。

### 10.2 人工部分

1. 在微信公众平台把最新开发版本设为体验版；
2. 使用 iOS、Android 真机完成登录、手机号授权、查看题目、提交答案、结果、榜单和个人中心回归；
3. 核对隐私保护指引、服务类目、审核页面和测试账号；
4. 提交微信审核；
5. 审核通过后人工发布；
6. 使用非项目成员微信完成线上回归；
7. 在发布记录中填写微信版本、审核时间和发布时间。

小程序正式包禁止包含 `localhost`、`127.0.0.1`、内网 IP、测试用户或 mock 登录。API 保持至少一个已发布小程序版本的向后兼容，防止微信审核期间服务端先行变更导致旧包不可用。

## 11. 备份、恢复和回退

### 11.1 应用回退

- Jenkins 健康检查失败自动恢复上一 `current`；
- 人工回退也只能选择 `releases` 中已成功版本；
- 回退后重新执行本机和公网三项健康检查；
- 每次回退记录操作者、原因、前后版本和时间；
- 管理后台和后端作为一个发布单元一起回退，避免接口版本错配。

### 11.2 数据库恢复

- 当前同机 MySQL 必须配置每日逻辑备份，并复制到 ECS 之外的受控存储；
- 含迁移发布前建立手动备份，记录文件校验值和恢复验证结果；
- 严重故障时先恢复到临时数据库验证，再切换应用连接，不在原库盲目覆盖；
- 每季度至少执行一次恢复演练，记录 RPO、RTO 和验证结果；
- 迁移 RDS 后启用数据备份和日志备份，并将恢复策略更新为时间点恢复；
- 首次上线阶段目标：RPO 不超过 24 小时，RTO 不超过 4 小时；迁移 RDS 后再提高目标。

### 11.3 小程序回退

- 微信端使用版本管理中的上一正式版本回退；
- 回退前确认上一小程序版本仍兼容当前 API；
- 服务端不得因为小程序回退而泄露标准答案或绕过登录；
- 回退后用非项目成员微信完成核心链路复测。

### 11.4 ECS 故障恢复

- 首版 Jenkins、Nginx、Java 和 MySQL 共用一台 ECS，因此 ECS 故障会造成服务和数据库同时中断；本方案提供可恢复能力，不承诺服务器级零停机；
- 代码和 `Jenkinsfile` 从 GitHub 公开仓库恢复；生产数据必须依赖系统盘快照加异地数据库备份双重恢复，不能只留在 ECS；
- 优先从最近一次健康系统盘快照创建新 ECS；快照不可用时按第 13 节重新安装运行环境；
- 恢复 `/opt/soft-energy/shared` 前核对配置备份来源和权限，不从 Jenkins 控制台日志复制密钥；
- 公网 IP 变化时同步更新 DNS、微信合法域名指向和运维记录；
- 启动 Nginx、Jenkins 和 `soft-energy-api` 后执行完整公网回归；
- ECS 恢复目标 RTO 不超过 2 小时，业务规模未达到双机需求前不增加负载均衡和第二应用节点。

## 12. 日志、监控和告警

### 12.1 保留策略

| 内容 | 保留时间 |
| --- | --- |
| Java/systemd 应用日志 | 30 天 |
| Nginx 访问和错误日志 | 30 天 |
| Jenkins 构建记录 | 90 天或最近 30 次，以先达到者为准 |
| 管理员业务审计日志 | 180 天 |
| MySQL 每日逻辑备份 | 本机 7 天，异地副本至少 14 天 |
| ECS 系统盘自动快照 | 7 天 |

日志禁止输出完整手机号、微信 AppSecret、JWT、数据库密码、管理员密码、标准答案全文和用户原始敏感资料。请求使用 `traceId` 关联，管理员敏感操作写业务审计表。

### 12.2 固定告警

- ECS CPU 连续 5 分钟超过 80%；
- ECS 内存超过 85%；
- ECS 磁盘超过 80%；
- API 连续 3 次健康检查失败；
- Nginx 5xx 在 5 分钟内异常升高；
- MySQL 连接数超过上限 70%，或慢查询/异常退出；
- MySQL 自动备份或异地复制失败；
- TLS 证书剩余不足 30 天；
- Jenkins 正式发布失败或发生自动回退。

告警联系人手机号和邮箱属于上线资料，在阿里云控制台和 Jenkins 中配置，不写入仓库。
